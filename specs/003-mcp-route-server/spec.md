# Feature Specification: MCP 경로 검색 서버

**Feature Branch**: `003-mcp-route-server`

**Created**: 2026-07-01

**Status**: Draft

**Input**: User description: "naeryeo mcp 서브커맨드: internal/core의 대중교통 경로 검색 로직을 Claude Desktop/Claude Code 같은 MCP 클라이언트에 stdio 기반 MCP 서버로 노출한다. 사용자가 Claude Desktop/Code에서 \"지금 강남역에서 홍대입구역까지 대중교통으로 어떻게 가?\" 같은 자연어 질문을 하면, MCP 클라이언트가 naeryeo mcp 프로세스를 도구(tool) 호출로 실행해 출발지/도착지를 넘기고, naeryeo는 internal/core.FindRoute 결과(소요시간, 환승 횟수, 요금, 단계별 안내 또는 이동 불필요/에러 사유)를 MCP 클라이언트가 자연어로 사용자에게 설명할 수 있는 구조화된 형태로 반환한다. API 키가 설정되지 않았거나 유효하지 않은 경우, 인식할 수 없는 지점이거나 경로가 없는 경우 각각 MCP 클라이언트가 사용자에게 그 사유를 그대로 전달할 수 있도록 명확한 에러 정보를 반환해야 한다. 이 서버는 로컬에서 실행되는 개인용 도구이며 MCP 클라이언트가 프로세스를 직접 실행하고 종료를 관리하는 stdio 모델을 사용한다(README의 '왜 stdio인가' 참고). CLI의 route 서브커맨드와 동일한 internal/core 로직을 공유하며, 진입점(프로토콜 처리)만 다르다."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Claude Desktop/Code에서 자연어로 경로 질문 (Priority: P1)

사용자가 Claude Desktop이나 Claude Code에서 "지금 강남역에서 홍대입구역까지 대중교통으로 어떻게 가?" 같은 자연어 질문을 하면, 별도로 터미널을 열거나 CLI 명령을 입력하지 않고도 대중교통 경로(총 소요시간, 환승 횟수, 요금, 단계별 이동 안내)를 답으로 받는다.

**Why this priority**: MCP 서버로서 naeryeo가 존재하는 이유 그 자체다. 이 흐름이 없으면 "Claude Desktop/Code에 연결해서 쓴다"는 제품의 핵심 약속이 성립하지 않는다.

**Independent Test**: 이미 API 키가 설정된 상태에서, 실제로 대중교통으로 연결된 두 지점의 이름을 서버에 전달했을 때 총 소요시간·환승 횟수·요금·단계별 안내가 모두 포함된 응답을 받는 것으로 독립적으로 검증 가능하다(CLI `route`의 User Story 1과 동일한 검증 데이터 사용 가능).

**Acceptance Scenarios**:

1. **Given** API 키가 설정되어 있고 두 지점이 모두 실제 존재하며 대중교통으로 연결된 상태, **When** 출발지·도착지 이름으로 경로 검색이 요청되면, **Then** 총 소요시간, 환승 횟수, 요금, 단계별 이동 안내가 모두 포함된 응답을 받는다.
2. **Given** 출발지와 도착지가 이동이 필요 없을 만큼 가까운 지점인 상태, **When** 경로 검색이 요청되면, **Then** 오류가 아니라 "이동이 필요 없음"을 알리는 응답을 받는다.
3. **Given** 하나의 대화 세션 안에서 이미 한 번 경로를 물어본 상태, **When** 다른 출발지·도착지 조합으로 다시 경로를 물어보면, **Then** 서버를 다시 시작하지 않고도 새 질문에 대한 응답을 받는다(연속 질의).

---

### User Story 2 - API 키 문제에 대한 안내 (Priority: P1)

API 키가 아직 설정되지 않았거나 저장된 키가 더 이상 유효하지 않은 상태에서 사용자가 경로를 물어보면, Claude가 "API 키가 없다"거나 "키가 유효하지 않다"는 사실과 무엇을 해야 하는지(예: `naeryeo setup` 실행)를 사용자에게 그대로 전달할 수 있다.

**Why this priority**: 이 안내가 없으면 사용자는 MCP 응답이 왜 실패했는지 전혀 알 수 없어 첫 사용 경험이 크게 나빠진다. CLI(`route`)의 동등한 요구사항과 마찬가지로 초기 릴리스에 반드시 필요하다.

**Independent Test**: API 키가 저장되지 않은 상태와, 저장은 되어 있지만 유효하지 않은 상태 각각에서 경로 검색을 요청해, 서로 구분되는 사유가 응답에 담겨 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** API 키가 저장되어 있지 않은 상태, **When** 경로 검색이 요청되면, **Then** 응답에는 API 키가 설정되지 않았다는 사실과 `naeryeo setup` 실행이 필요하다는 안내가 담겨 있다.
2. **Given** 저장된 API 키가 유효하지 않은 상태, **When** 경로 검색이 요청되면, **Then** 응답에는 "키 미설정"과는 다른, 키가 유효하지 않다는 사유가 담겨 있다.

---

### User Story 3 - 인식 불가 지점·경로 없음·서비스 장애에 대한 안내 (Priority: P2)

사용자가 오타가 있거나 존재하지 않는 지점을 언급했거나, 두 지점 사이에 대중교통 경로가 없거나, 외부 경로 검색 서비스에 일시적 장애가 있는 경우에도 서버가 멈추거나 죽지 않고 원인을 설명하는 응답을 돌려줘서 Claude가 사용자에게 그대로 전달할 수 있다.

**Why this priority**: 핵심 성공 경로(User Story 1)가 갖춰진 뒤에 다뤄야 할 예외 처리이지만, 이 안내가 없으면 서버가 응답 없이 멈춘 것처럼 보이거나 사용자가 원인 불명의 실패를 반복해서 겪게 되므로 초기 릴리스에 포함되어야 한다.

**Independent Test**: 존재하지 않는 지점, 연결되지 않는 두 지점, 그리고 외부 서비스 장애 상황 각각을 재현해 서버가 죽지 않고 각기 다른 사유가 담긴 응답을 반환하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 출발지 또는 도착지 이름이 실제 지점과 일치하지 않는 상태, **When** 경로 검색이 요청되면, **Then** 응답에는 어느 지점을 인식하지 못했는지 알 수 있는 사유가 담겨 있고 서버는 계속 다음 요청을 받을 수 있는 상태로 남아 있다.
2. **Given** 두 지점 모두 유효하지만 대중교통으로 연결되지 않는 상태, **When** 경로 검색이 요청되면, **Then** 응답에는 "경로 없음"이라는 사유가 담겨 있다.
3. **Given** 외부 경로 검색 서비스가 일시적으로 응답하지 않는 상태, **When** 경로 검색이 요청되면, **Then** 서버는 무한정 대기하거나 예기치 않게 종료되지 않고 원인을 설명하는 응답을 반환하며, 이후 요청도 계속 처리할 수 있다.

### Edge Cases

- 사용자가 출발지 또는 도착지 중 하나를 언급하지 않은 채로 질문한 경우, 어떤 안내를 받는가?
- 사용자가 Claude Desktop/Code를 종료하면 실행 중이던 서버 프로세스는 어떻게 정리되는가?
- 서버가 시작된 후 아무 질문도 없이 오래 유휴 상태로 있다가 다시 질문을 받는 경우에도 정상 응답하는가?
- 서버 시작 직후(첫 질문 이전) API 키 확인 등 준비 과정에서 실패가 발생하면 어떻게 되는가?

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 MCP 클라이언트로부터 전달받은 출발지·도착지에 대해 대중교통 경로를 검색해 응답해야 한다.
- **FR-002**: 응답에는 총 소요시간, 환승 횟수, 요금, 단계별 이동 안내가 포함되어야 한다.
- **FR-003**: 출발지와 도착지가 이동이 필요 없을 만큼 가까운 경우, 시스템은 이를 오류가 아니라 "이동 불필요" 응답으로 알려야 한다.
- **FR-004**: API 키가 설정되지 않은 상태에서 요청이 오면, 시스템은 그 사실과 `naeryeo setup` 실행이 필요하다는 사유가 담긴 응답을 반환해야 한다.
- **FR-005**: 저장된 API 키가 유효하지 않아 인증에 실패하면, 시스템은 이를 "키 미설정"과 구분되는 사유로 응답해야 한다.
- **FR-006**: 출발지 또는 도착지를 인식할 수 없는 경우, 시스템은 어느 쪽을 인식하지 못했는지 알 수 있는 사유가 담긴 응답을 반환해야 한다.
- **FR-007**: 두 지점 사이에 대중교통 경로가 존재하지 않는 경우, 시스템은 "경로 없음"이라는 사유가 담긴 응답을 반환해야 한다.
- **FR-008**: 외부 경로 검색 서비스 호출이 실패(네트워크 오류, 서비스 장애 등)하는 경우, 시스템은 무한정 대기하거나 예기치 않게 종료되지 않고 원인을 설명하는 응답을 반환해야 한다.
- **FR-009**: 시스템은 하나의 실행 세션 동안 여러 번의 경로 검색 요청을 순서대로 계속 처리할 수 있어야 한다(한 번의 실패나 에러 응답이 이후 요청 처리를 막지 않음).
- **FR-010**: 시스템은 MCP 클라이언트가 프로세스를 시작하면 별도의 초기 설정 절차 없이(이미 저장된 API 키를 전제로) 즉시 요청을 처리할 준비가 되어야 한다.
- **FR-011**: 시스템은 MCP 클라이언트가 프로세스 종료를 요청하면 정상적으로 종료되어야 한다.
- **FR-012**: 이 기능은 CLI `route` 서브커맨드와 동일한 경로 검색 핵심 로직을 공유해야 하며, 동일한 출발지·도착지 입력에 대해 두 진입점이 항상 같은 경로 검색 결과를 내야 한다.

### Key Entities

- **경로 검색 요청**: MCP 클라이언트가 전달하는 출발지 명칭과 도착지 명칭으로 구성된다(CLI `route`의 요청과 동일한 정보).
- **경로 검색 응답**: 성공 시 총 소요시간·환승 횟수·요금·단계별 이동 안내(또는 이동 불필요 표시)를, 실패 시 실패 사유(키 미설정/키 무효/지점 인식 불가/경로 없음/서비스 장애)를 구분해서 담는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 실제로 대중교통으로 연결된 두 지점에 대한 요청의 95%는 10초 이내에 총 소요시간·환승 횟수·요금·단계별 안내가 모두 포함된 응답으로 처리된다(외부 경로 검색 서비스가 정상 응답하는 경우 기준).
- **SC-002**: API 키가 설정되지 않았거나 유효하지 않은 상태에서의 요청 100%는 두 상황을 구분할 수 있는 사유가 담긴 응답으로 처리된다.
- **SC-003**: 인식할 수 없는 지점이 포함되었거나 경로가 없는 요청의 100%는 원인을 알 수 있는 사유가 담긴 응답으로 처리되며, 서버 프로세스가 죽거나 응답 없이 멈추지 않는다.
- **SC-004**: 한 번의 실행 세션 안에서 연속으로 여러 번(예: 10회) 요청해도 100%가 각각 독립적으로 정상 처리된다(이전 요청의 실패가 이후 요청에 영향을 주지 않음).
- **SC-005**: 동일한 출발지·도착지 입력에 대해 CLI(`route`)와 이 기능(MCP) 양쪽에서 항상 동일한 경로 검색 결과를 얻는다.

## Assumptions

- API 키는 이미 `naeryeo setup`([[001-keychain-api-key]])으로 저장되어 있는 것을 전제로 하며, 키 저장/조회/삭제 자체는 이 기능의 범위가 아니다.
- 경로 검색 핵심 로직(이름→좌표 변환, ODsay 호출, 에러 분류)은 이미 존재하는 기능([[002-odsay-route-search]])을 그대로 재사용하며, 이 기능은 그 로직을 MCP 클라이언트에게 노출하는 진입점만 다룬다.
- Claude Desktop/Code에 naeryeo를 도구로 등록하는 절차(설정 파일 편집)는 사용자가 README를 따라 수동으로 수행하는 것으로 가정하며, 이 기능의 범위는 서버 자체의 동작(요청을 받아 응답하는 것)으로 한정한다.
- 이 서버는 로컬에서 실행되는 개인용 도구로, 한 번에 하나의 MCP 클라이언트만 연결되는 것을 전제로 한다. 여러 클라이언트의 동시 접속이나 다중 사용자 인증/권한 분리는 범위 밖이다.
- 요청은 실질적으로 순차적으로 도착하는 것으로 가정하며(로컬 단일 사용자 시나리오), 대량 동시 요청에 대한 성능 보장은 이 기능의 범위가 아니다.
