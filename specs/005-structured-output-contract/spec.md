## User Scenarios & Testing *(mandatory)*

이 기능의 1차 사용자는 **naeryeo를 도구로 호출하는 AI 에이전트**다. 사람 사용자는 2차
사용자이며, 이 기능은 사람이 보는 출력을 바꾸지 않는 것을 제약으로 삼는다.

### User Story 1 - AI가 실패 원인을 코드로 구분해 다음 행동을 결정한다 (Priority: P1)

AI 에이전트가 경로 검색을 요청했다가 실패했을 때, 자연어 문장을 해석하지 않고도
"지금 재시도해야 하는가 / 입력을 바꿔 다시 물어야 하는가 / 사용자에게 키 설정을
요구해야 하는가"를 판별할 수 있어야 한다. 지금은 실패 이유가 한국어 문장 하나로만
전달되어, 에이전트가 문자열 매칭에 의존하거나 의미 없는 재시도 루프를 돈다.

**Why this priority**: 이 기능이 존재하는 이유 자체다. 성공 결과는 이미 자연어로도
충분히 전달되지만, 실패는 "다음에 무엇을 할 것인가"라는 분기를 만들기 때문에
기계 판독 가능한 신호가 없으면 에이전트가 잘못 행동한다. 특히 "잠시 후 재시도"와
"입력을 재작성"은 정반대의 행동인데 현재는 두 한국어 문장의 차이로만 구별된다.

**Independent Test**: 각 실패 상황을 유발한 뒤, 출력에 담긴 코드만으로 올바른 후속
행동을 고를 수 있는지 확인한다. 문장 내용을 전혀 읽지 않고도 분기가 가능하면 통과.

**Acceptance Scenarios**:

1. **Given** 장소 검색 서비스가 호출 빈도 제한으로 요청을 거절한 상태, **When** AI가
   기계 판독 모드로 경로를 검색하면, **Then** "잠시 후 재시도"를 뜻하는 코드가
   반환되고, 같은 요청을 그대로 다시 보내는 것이 올바른 행동임을 알 수 있다.
2. **Given** 입력한 위치를 인식할 수 없는 상태, **When** AI가 기계 판독 모드로 경로를
   검색하면, **Then** "입력 재작성"을 뜻하는 코드가 반환되어 시나리오 1과 명확히
   구분되고, 동일 입력 재시도가 무의미함을 알 수 있다.
3. **Given** 장소 검색 키가 인증에 실패한 상태, **When** AI가 기계 판독 모드로 경로를
   검색하면, **Then** "키 재등록으로 해결 가능"을 뜻하는 코드가 반환된다.
4. **Given** 장소 검색 키는 유효하나 제공자 콘솔 설정 때문에 권한이 거부된 상태,
   **When** AI가 기계 판독 모드로 경로를 검색하면, **Then** 시나리오 3과 **다른**
   코드가 반환되어, 키를 다시 등록해도 소용없음을 알 수 있다.
5. **Given** 출발지만 인식되지 않은 상태, **When** AI가 기계 판독 모드로 경로를
   검색하면, **Then** 어느 쪽(출발지/도착지/양쪽)이 실패했는지와 그 입력값이 함께
   반환되어, 실패한 지점만 골라 다시 질의할 수 있다.
6. **Given** 임의의 실패 상황, **When** 기계 판독 모드로 요청하면, **Then** 실패
   문서에 코드와 사람에게 그대로 전달할 수 있는 안내 문구가 **모두** 포함된다.

### User Story 2 - AI가 성공 결과를 파싱 없이 소비한다 (Priority: P2)

AI 에이전트가 경로 검색에 성공했을 때, 소요시간·환승 횟수·요금·단계 목록을 자연어
출력에서 뽑아내지 않고 구조화된 형태로 바로 받는다. 같은 데이터가 두 개의 다른
구조로 갈라지지 않도록, 커맨드라인 경로와 상시 서버 경로의 성공 결과 구조는 동일해야
한다.

**Why this priority**: 실패 처리(P1)만큼 행동을 좌우하지는 않지만, 기계 판독 모드를
선언한 호출자가 성공일 때만 자연어를 받는다면 계약이 성립하지 않는다. P1과 함께 하나의
출력 모드를 이룬다.

**Independent Test**: 성공하는 경로 검색을 기계 판독 모드로 실행하고, 그 결과 구조가
상시 서버 경로의 성공 결과 구조와 필드 단위로 일치하는지 비교한다.

**Acceptance Scenarios**:

1. **Given** 유효한 출발지·도착지, **When** 기계 판독 모드로 검색하면, **Then**
   총 소요시간·환승 횟수·요금·단계 목록이 구조화된 형태로 반환된다.
2. **Given** 출발지와 도착지가 이동이 필요 없을 만큼 가까운 경우, **When** 기계 판독
   모드로 검색하면, **Then** "이동 불필요" 상태가 별도 값으로 표현되어, 소요시간 0을
   경로 실패로 오해하지 않는다.
3. **Given** 임의의 성공 검색, **When** 커맨드라인 경로와 상시 서버 경로 양쪽에서
   같은 검색을 실행하면, **Then** 두 성공 결과의 구조가 동일하다.

### User Story 3 - 내부·업스트림 오류 원문이 어디로도 새지 않는다 (Priority: P3)

경로 제공자나 자격증명 저장소가 예상 밖의 오류를 돌려주었을 때, 그 원문(제공자 서버의
내부 메시지, 추적 ID, 저장소 오류 문자열)이 사람 사용자에게도 AI에게도 노출되지
않는다. 현재는 분류되지 않은 오류가 그대로 출력되어 이해할 수 없는 내부 정보가 새고,
AI는 그것을 사용자에게 그대로 전달한다.

**Why this priority**: 이미 발생하고 있는 결함이고 P1의 코드 체계를 빠짐없이 만들면
자연히 해소되지만, 단독으로도 가치가 있으므로 별도 스토리로 둔다. 사람용 출력에도
영향을 주는 유일한 스토리다.

**Independent Test**: 분류되지 않은 원인이 감싸진 형태의 오류를 주입하고, 사람용
출력과 기계 판독 출력 어디에도 원문 문자열이 나타나지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 경로 제공자가 분류되지 않은 오류 코드와 내부 메시지를 반환한 상태,
   **When** 사람용 모드로 경로를 검색하면, **Then** 제공자의 내부 메시지가 출력에
   나타나지 않고 조치 가능한 안내만 표시된다.
2. **Given** 동일 상태, **When** 기계 판독 모드로 검색하면, **Then** 해당 상황에
   대응하는 코드가 반환되고 제공자 원문은 포함되지 않는다.
3. **Given** 자격증명 저장소 조회가 실패한 상태, **When** 커맨드라인·상시 서버 어느
   경로로 요청해도, **Then** 저장소의 원본 오류 문자열 대신 분류된 코드와 안내가
   반환된다.
4. **Given** 새로운 실패 원인이 시스템에 추가되었으나 코드가 부여되지 않은 상태,
   **When** 품질 게이트를 실행하면, **Then** 누락이 자동으로 발견되어 실패한다.

---

### Edge Cases

- 기계 판독 모드에서 **실패**했을 때 결과 문서를 어디로 보낼 것인가 — 출력을 한 번만
  캡처하는 호출자가 실패 이유를 통째로 잃으면 안 된다.
- 진단 모드와 기계 판독 모드를 **함께** 지정했을 때, 진단 정보가 기계 판독 문서를
  오염시켜 파싱을 깨뜨리면 안 된다.
- 하나의 실패 유형이 서로 다른 후속 행동으로 갈리는 경우(장소 검색 거절 = 빈도 제한
  vs 잘못된 입력) — 코드는 내부 분류가 아니라 **후속 행동** 기준으로 갈라져야 한다.
- 지점 인식 실패 시 장소 검색 키가 이미 설정되어 있으면, "키를 설정하라"는 조치 안내는
  붙지 않아야 한다.
- 명령을 잘못 호출한 경우(필수 인자 누락 등)에도 기계 판독 모드를 지정했다면 파싱
  가능한 응답이 나와야 한다.
- 기존 사람용 출력을 소비하는 스크립트·문서가 깨지지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**에러 코드 체계**

- **FR-001**: 시스템은 경로 검색이 실패할 수 있는 모든 상황에 대해, 호출자가 취해야 할
  후속 행동과 1:1로 대응하는 **안정적인 식별자(에러 코드)** 를 부여해야 한다.
- **FR-002**: 코드는 내부 오류 분류가 아니라 **후속 행동** 기준으로 구분되어야 한다.
  같은 내부 원인이라도 후속 행동이 다르면 다른 코드를 가져야 하고, 다른 내부 원인이라도
  후속 행동이 같으면 같은 코드를 가질 수 있다.
- **FR-003**: 아래 상황들은 각각 서로 구별되는 코드를 가져야 한다. 이 표는 **최소 집합**이며,
  다른 요구사항이 추가 코드를 요구할 수 있다 — FR-015(인자 검증 실패)와 FR-005(미분류 실패의
  안전한 기본값)가 각각 하나씩 더 요구한다.

  | 실패 상황 | 호출자의 올바른 후속 행동 |
  | --- | --- |
  | 경로 검색 키 미설정 | 사용자에게 초기 설정을 안내 |
  | 경로 검색 키가 거부됨 | 사용자에게 키 재등록을 안내 |
  | 장소 검색 키가 인증에 실패 | 사용자에게 장소 검색 키 재등록을 안내 |
  | 장소 검색 권한이 거부됨(제공자 콘솔 설정 문제) | 콘솔 설정 확인 안내 — 재등록은 무의미 |
  | 장소 검색 호출 빈도 제한 | 잠시 후 **동일 요청 재시도** |
  | 장소 검색이 요청을 거절(그 외) | **입력 재작성** — 재시도 무의미 |
  | 출발지/도착지를 인식하지 못함 | 실패한 쪽만 다시 질의 |
  | 두 지점 사이에 경로가 없음 | 사용자에게 보고 — 재시도 금지 |
  | 장소 검색 서비스 연결 불가 | 잠시 후 재시도 |
  | 경로 검색 서비스 연결 불가 | 잠시 후 재시도 |
  | 경로 검색 서비스가 요청을 거절 | 사용자에게 보고 — 재시도 금지 |
  | 자격증명 저장소 조회 실패 | 사용자에게 보고 |

- **FR-004**: 코드가 부여되지 않은 실패 원인이 남아 있으면 **자동화된 품질 게이트가
  실패**해야 한다. 새로운 실패 원인이 추가될 때 코드 부여를 강제하는 장치여야 한다.
- **FR-005**: 어떤 실패에 대해서도 분류되지 않은 채 원본 오류가 그대로 출력되는 경로가
  존재해서는 안 된다.

**출력 모드**

- **FR-006**: 사용자는 경로 검색 명령에서 **기계 판독 출력 모드를 명시적으로 선택**할 수
  있어야 한다. 선택하지 않으면 기존 사람용 출력이 그대로 유지된다.
- **FR-007**: 기계 판독 모드를 선택하지 않았을 때의 출력 내용·스트림·종료 코드는
  현재와 동일해야 한다. 단, FR-005에 의해 원본 오류가 새던 경우의 문구는 바뀐다.
- **FR-008**: 기계 판독 모드에서는 **성공과 실패 모두 같은 스트림에 하나의 문서로**
  출력되어야 한다. 출력을 한 번 캡처하거나 파이프로 넘기는 호출자가 실패 이유를 잃지
  않아야 한다.
- **FR-009**: 성공과 실패는 **종료 코드로** 구분되어야 한다. 실패는 원인과 무관하게
  단일 실패 종료 코드를 사용한다.
- **FR-010**: 기계 판독 모드의 **성공** 문서 구조는 상시 서버(MCP) 경로의 성공 결과
  구조와 **동일**해야 하며, 이 동일성은 자동 검증되어야 한다.
- **FR-011**: 기계 판독 모드의 **실패** 문서는 코드와 사람에게 전달할 안내 문구를 항상
  포함해야 한다. 안내 문구는 현재 사람용 출력이 제공하는 것과 동일한 수준의 정보를
  담아야 한다.
- **FR-012**: 지점 인식 실패 시에는 실패한 쪽(출발지/도착지/양쪽)과 해당 입력값이 실패
  문서에 함께 담겨야 한다.
- **FR-013**: 사용자가 취할 **조치 안내**는 실패 사유와 구분되어 표현되어야 한다.
  (사람용 출력에서는 지금처럼 이어 붙여 출력해 하위 호환을 유지한다.)
- **FR-014**: 진단 모드와 기계 판독 모드가 동시에 지정되어도 기계 판독 문서의 파싱
  가능성이 유지되어야 한다.
- **FR-015**: 인자 검증 실패(필수 인자 누락 등)도 기계 판독 모드에서는 같은 실패 문서
  형식으로 반환되어야 한다.

**엔트리포인트 일관성**

- **FR-016**: 커맨드라인 경로와 상시 서버 경로는 **같은 실패에 같은 코드와 같은 안내
  문구**를 반환해야 하며, 이 일치는 자동 검증되어야 한다.
- **FR-017**: 상시 서버 경로의 실패 응답은 자연어 문장뿐 아니라 **구조화된 형태로도**
  코드를 전달해야 한다.
- **FR-018**: 자격증명 저장소 조회 실패는 두 경로 모두에서 같은 코드 체계로 처리되어야
  한다.

**문서**

- **FR-019**: AI용 스킬 문서는 실패 유형을 산문으로 나열하는 대신 **코드 기준으로**
  재작성되어야 하며, 특히 "재시도"와 "입력 재작성", "키 재등록"과 "콘솔 설정 확인"의
  구분이 명시되어야 한다.
- **FR-020**: AI용 스킬 문서는 기계 판독 모드를 1순위 호출 형태로 제시해야 한다.
- **FR-021**: 스킬 문서에 인용된 실패 문구가 실제 출력과 어긋나 있으면 코드 기준으로
  정정되어야 한다.

### Key Entities

- **에러 코드**: 실패 상황을 후속 행동 단위로 식별하는 안정적인 문자열. 한 번 공개되면
  호환성 계약의 일부가 된다.
- **실패 문서**: 코드 + 사람에게 전달할 안내 문구를 필수로 갖고, 상황에 따라 조치 안내와
  실패 지점 정보(어느 쪽·입력값)를 추가로 갖는 구조.
- **성공 문서**: 총 소요시간·환승 횟수·요금·단계 목록, 그리고 "이동 불필요" 상태를 담는
  구조. 상시 서버 경로의 성공 결과와 동일한 구조여야 한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: AI 호출자가 실패 응답의 **문장을 전혀 읽지 않고** 코드만으로 FR-003이
  나열한 12개 실패 상황 전부에 대해 올바른 후속 행동을 선택할 수 있다. (FR-003이 최소
  집합이므로 실제 코드 수는 이보다 많을 수 있다.)
- **SC-002**: "잠시 후 재시도가 유효한 실패"와 "재시도가 무의미한 실패"가 100%
  구별 가능하다 — 무의미한 재시도 루프가 구조적으로 불가능해진다.
- **SC-003**: 어떤 실패 경로에서도 외부 제공자나 저장소의 원본 메시지가 사용자·AI에게
  노출되지 않는다 (노출 사례 0건).
- **SC-004**: 새로운 실패 원인을 코드 부여 없이 추가하면 품질 게이트가 반드시 실패한다.
- **SC-005**: 커맨드라인 경로와 상시 서버 경로가 같은 실패에 대해 서로 다른 코드나
  문구를 내는 경우가 0건이다.
- **SC-006**: 기계 판독 모드의 출력은 성공·실패 모두 단일 문서로 파싱 가능하며, 출력을
  한 번만 캡처하는 호출자가 실패 이유를 잃는 경우가 0건이다.
- **SC-007**: 기존 사람용 출력을 검증하는 테스트가 FR-005 해당 케이스를 제외하고 전부
  변경 없이 통과한다.
- **SC-008**: 스킬 문서가 나열하는 실패 유형과 실제 코드 집합이 일치한다 — 문서에만
  존재하거나 코드에만 존재하는 실패 유형이 0건이다.

## Assumptions

아래는 명세 작성 시 근거를 두고 선택한 기본값이다. GYE-292의 설계 논의와 프로젝트
헌법(원칙 I: 추상화는 복잡도를 정당화해야 한다)을 기준으로 삼았다.

- **적용 범위는 경로 검색 명령에 한정한다.** 대화형 설정 명령은 사람과의 대화가 목적이라
  기계 판독 모드가 의미가 없다.
- **실패 문서도 성공과 같은 스트림(표준 출력)으로 보낸다.** 결과에 따라 문서가 두
  스트림으로 갈리면 한 번의 캡처로 파싱할 수 없고, 표준 출력만 잡는 호출자는 빈 출력과
  실패 종료 코드만 보게 되어 정작 가장 중요한 실패 이유를 잃는다. 표준 출력으로
  리다이렉트하는 스크립트가 실패 문서를 받게 되는 트레이드오프는 종료 코드로 걸러진다.
- **진단 모드의 원본 정보는 기계 판독 문서에 포함하지 않고 별도 스트림으로 보낸다.**
  FR-008의 "단일 문서" 불변식을 깨지 않는 유일한 방식이다.
- **아직 발생할 수 없는 실패 상황에 대한 코드는 만들지 않는다.** GYE-292 원안은
  `provider_not_configured`(GYE-294가 도입할 설정 파일 부재 상태)와 문서 링크 필드
  (GYE-295가 처음 사용)를 미리 자리만 만들어 두는 안을 담고 있으나, 이 명세는 이를
  범위에서 제외한다 — 생산자가 없는 코드는 FR-004의 망라성 검증이 다룰 대상이 없고,
  헌법 원칙 I의 "추측성 일반화 금지"에 어긋난다. GYE-294·GYE-295가 각자 자신의 실패
  상황을 추가할 때 FR-004의 게이트가 코드 부여를 자동으로 강제한다.
- **조치 안내는 실패 사유와 별도 필드로 분리한다.** AI가 "사용자에게 전달할 이유"와
  "사용자가 취할 조치"를 구분할 수 있게 하기 위함이다. 사람용 출력은 지금처럼 이어
  붙여 출력해 하위 호환을 유지한다.
- **실패 종료 코드는 원인별로 분화하지 않는다.** 문서에 코드가 이미 있으므로 종료 코드
  분화는 중복 계약이 되고 동기화 대상만 늘어난다.
- **안내 문구는 한국어를 유지한다.** AI가 한국어 사용자에게 그대로 전달할 문구이며,
  현재 문구에 축적된 안내 품질을 버릴 이유가 없다.

## Dependencies

- **선행**: 없음. 이 기능은 독립적으로 완료 가능하다.
- **후속**: GYE-294(provider 설정 모델)와 GYE-295(대체 경로 제공자)가 각자 도입하는 실패
  상황을 이 명세가 만든 코드 체계 위에 추가한다. 따라서 이 기능이 먼저 완료되어야 한다.
- **병행 주의**: GYE-294·GYE-295도 AI용 스킬 문서를 수정한다. 먼저 병합되는 쪽을 기준으로
  재조정한다.
- **관련**: GYE-293(경로 검색 API 키 평문 유출 차단, 완료됨)은 원본 오류 값 자체를
  소스 레벨에서 가려 두었다. 이 명세는 그 위에서 **표현 계층 전반**을 담당한다.

## Out of Scope

- 실패 원인별 종료 코드 분화
- 기계 판독 모드를 지정하지 않았을 때의 문구·스트림 변경 (FR-005 해당 케이스 제외)
- 진단 모드 자체의 동작 변경 및 비밀값 가림 처리 (GYE-293에서 완료)
- 경로 제공자 선택 설정 모델 (GYE-294)
- 대체 경로 제공자 도입 및 그에 따른 실패 상황 (GYE-295)
- 대화형 설정 명령의 기계 판독 모드 지원
