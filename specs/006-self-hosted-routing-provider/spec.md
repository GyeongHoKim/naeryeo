**Feature Branch**: `006-self-hosted-routing-provider`

**Created**: 2026-07-31

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

현재 naeryeo를 쓰려면 **예외 없이** 상용 경로 검색 API의 계정을 만들고 키를 발급받아야
한다. 그 상용 서비스의 무료 한도·과금 정책·약관이 바뀌면 naeryeo 사용자 전원의 사용
가능 여부가 함께 흔들린다. 이 기능은 사용자가 **자기 인프라에서 경로 검색 엔진을 직접
운영**하는 선택지를 추가해, naeryeo를 쓰기 위해 외부 사업자의 정책에 종속될 필요를
없앤다.

1차 사용자는 **자체 호스팅을 원하는 사람 사용자**다. 상용 API를 계속 쓰려는 기존
사용자는 이 기능 때문에 손해를 보지 않아야 하고, naeryeo를 호출하는 AI 에이전트는
제공자가 무엇이든 동일한 방식으로 동작해야 한다.

### User Story 1 - 상용 API 키 없이 자체 호스팅으로 경로를 검색한다 (Priority: P1)

상용 경로 검색 서비스에 가입하지 않은 사용자가, 자기가 운영하는 경로 검색 엔진을
naeryeo에 연결하고 그것만으로 경로 검색을 끝까지 수행한다. 설정 과정 어디에서도 상용
API 키를 요구받지 않는다.

**Why this priority**: 이 기능이 존재하는 이유 그 자체다. "자체 호스팅한 엔진으로 경로가
나온다"가 성립하지 않으면 나머지 모든 스토리는 의미가 없다. 이 스토리 하나만 완성돼도
"외부 사업자 정책에 종속되지 않는 naeryeo"라는 가치는 성립한다.

**Independent Test**: 상용 API 키가 저장되지 않은 깨끗한 환경에서 자체 호스팅 엔진만
연결한 뒤 경로 검색을 실행한다. 키 요구 없이 결과가 나오면 통과.

**Acceptance Scenarios**:

1. **Given** 어떤 경로 검색 키도 저장되지 않았고 자체 호스팅 엔진이 동작 중인 상태,
   **When** 사용자가 초기 설정에서 자체 호스팅을 선택하면, **Then** 상용 API 키 입력을
   요구받지 않고 엔진 주소 입력만으로 설정이 완료된다.
2. **Given** 자체 호스팅으로 설정을 마친 상태, **When** 경로를 검색하면, **Then** 총
   소요시간·환승 횟수·단계별 안내가 기존과 같은 형식으로 표시된다.
3. **Given** 자체 호스팅으로 설정을 마친 상태, **When** 커맨드라인 경로와 상시 서버(MCP)
   경로에서 각각 검색하면, **Then** 두 경로 모두 자체 호스팅 엔진을 사용한다 — 한쪽만
   상용 API로 갈라지는 일이 없다.
4. **Given** 자체 호스팅으로 설정을 마친 상태, **When** 기계 판독 모드로 검색하면,
   **Then** 성공 문서의 구조가 상용 API를 쓸 때와 동일하다.
5. **Given** 자체 호스팅 데이터에 요금 정보가 없는 경우, **When** 경로를 검색하면,
   **Then** "요금 정보 없음"이 요금 0원과 구분되어 표현된다.

### User Story 2 - 문서만 보고 자체 호스팅 환경을 처음부터 구축한다 (Priority: P2)

경로 검색 엔진을 운영해 본 적 없는 사용자가, naeryeo가 제공하는 문서만 따라가 자기
장비에 엔진을 띄우고 naeryeo와 연결한다. 필요한 데이터를 어디서 받는지, 얼마나 걸리고
얼마나 많은 자원이 필요한지를 시작 전에 알 수 있다.

**Why this priority**: 자체 호스팅은 "가능하다"만으로는 채택되지 않는다. 구축 경로가
문서로 재현되지 않으면 실제로 쓰는 사람은 없고, 기능은 있으나 아무도 못 쓰는 상태가
된다. 다만 P1이 없으면 문서가 가리킬 대상이 없으므로 P2다.

**Independent Test**: 자체 호스팅 경험이 없는 사람에게 문서만 주고 구축을 시키고, 문서
바깥의 지식(별도 검색, 저자에게 질문)이 필요했던 지점을 센다. 0이면 통과.

**Acceptance Scenarios**:

1. **Given** 자체 호스팅 문서, **When** 사용자가 처음부터 끝까지 따라가면, **Then**
   엔진 실행·데이터 준비·naeryeo 연결까지 문서 안에서 완결된다.
2. **Given** 자체 호스팅 문서, **When** 사용자가 착수 전에 읽으면, **Then** 필요한 저장
   공간·메모리·준비 시간의 실측 기준치를 미리 알 수 있다.
3. **Given** 자체 호스팅 문서의 절차, **When** 동일 절차를 다른 시점에 다시 수행하면,
   **Then** 같은 결과가 나온다 — 실행 대상과 데이터 출처의 버전이 고정되어 있다.
4. **Given** 자체 호스팅 문서, **When** 사용자가 읽으면, **Then** 자체 호스팅 데이터가
   상용 서비스와 비교해 어떤 한계(갱신 주기, 포함되지 않는 정보)를 갖는지 명시되어
   있어 기대치를 사전에 조정할 수 있다.
5. **Given** naeryeo의 시작 안내 문서, **When** 신규 사용자가 읽으면, **Then** 상용 API
   키 발급이 유일한 시작 경로처럼 보이지 않고 자체 호스팅이 동등한 선택지로 제시된다.

### User Story 3 - 자체 호스팅 엔진이 멈췄을 때 원인과 조치를 즉시 안다 (Priority: P3)

자체 호스팅은 운영 책임이 사용자에게 있으므로 엔진이 꺼져 있거나 주소가 틀린 상황이
일상적으로 발생한다. 이때 사람 사용자와 AI 에이전트 모두 "무엇이 잘못됐고 무엇을 해야
하는지"를 즉시 알 수 있어야 한다.

**Why this priority**: 없어도 P1의 경로 검색은 동작하지만, 자체 호스팅 사용자가 가장
자주 부딪히는 상황이 이것이다. 진단이 안 되면 사용자는 원인을 naeryeo로 오인하고
상용 API로 되돌아간다.

**Independent Test**: 엔진을 내린 상태와 주소를 잘못 설정한 상태를 각각 만들고, 사람용
출력과 기계 판독 출력이 각각 올바른 후속 행동으로 이어지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 자체 호스팅 엔진이 정지한 상태, **When** 경로를 검색하면, **Then** "연결할
   수 없음"이 재시도 가능한 실패로 구분되어 전달된다.
2. **Given** 동일 상태, **When** 기계 판독 모드로 검색하면, **Then** AI가 이를 사용자
   환경 문제로 인식하고, 같은 요청을 무한 반복하지 않는다.
3. **Given** 자체 호스팅 관련 실패, **When** 사람용·기계 판독 어느 모드로 보든, **Then**
   자체 호스팅 문서의 위치가 안내에 포함되어 사용자가 스스로 복구할 수 있다.
4. **Given** 자체 호스팅 엔진 주소가 사설망 호스트명·포트로 설정된 상태, **When** 실패
   안내가 출력되면, **Then** 그 호스트명·포트가 사람용·기계 판독 출력 어디에도 노출되지
   않는다.
5. **Given** 경로 제공자가 아직 선택되지 않은 상태, **When** 경로를 검색하면, **Then**
   "제공자 미설정"이 다른 실패와 구별되는 신호로 전달되고 초기 설정이 안내된다.

---

### User Story 4 - 기존 사용자가 한 번의 재설정으로 전환한다 (Priority: P4)

이미 상용 API 키로 naeryeo를 쓰고 있던 사용자가 업그레이드한다. 제공자를 아직 고르지
않은 상태이므로 첫 검색은 실패하지만, 그 실패가 무엇을 해야 하는지 정확히 알려주고,
초기 설정을 한 번 다시 실행하면 기존 사용을 그대로 이어가거나 자체 호스팅으로 옮길 수
있다.

**Why this priority**: 신규 가치를 만들지는 않지만, 이것이 없으면 기존 사용자를 잃는
방식으로 기능이 도착한다. P1~P3가 만든 것을 지키는 스토리다.

**Independent Test**: 기존 설정 상태(상용 API 키가 저장된 상태)를 그대로 둔 채
업그레이드하고, 사용자가 출력에 담긴 안내만 따라 정상 사용에 도달하기까지의 단계 수를
센다.

**Acceptance Scenarios**:

1. **Given** 상용 API 키를 이미 등록해 둔 기존 사용자, **When** 업그레이드 후 경로를
   검색하면, **Then** "제공자 미설정" 실패와 함께 초기 설정을 실행하라는 안내가 표시된다
   — 저장된 키를 근거로 제공자가 암묵적으로 결정되지 않는다.
2. **Given** 위 상태에서 사용자가 초기 설정을 다시 실행해 기존 상용 API 제공자를 선택한
   경우, **When** 경로를 검색하면, **Then** 이미 저장돼 있던 키가 그대로 재사용되어
   동작한다 — 키를 다시 발급받거나 다시 입력할 필요가 없다.
3. **Given** 상용 API를 쓰던 사용자, **When** 자체 호스팅으로 전환하면, **Then** 더 이상
   쓰지 않는 상용 API 키를 삭제할 수 있다.
4. **Given** 자체 호스팅을 쓰던 사용자, **When** 상용 API로 되돌리면, **Then** 전환이
   같은 설정 절차 안에서 가능하다.
5. **Given** 이번 변경으로 동작이 달라지는 지점, **When** 릴리스 안내를 읽으면,
   **Then** "초기 설정을 한 번 다시 실행해야 한다"와 그 이유가 사전에 고지되어 있다.

### Edge Cases

- 자체 호스팅 엔진 주소는 설정됐지만 그 주소가 경로 검색 엔진이 아닌 전혀 다른 서비스를
  가리키는 경우 — "연결 불가"와 구분되어야 하며, 응답 원문이 그대로 노출되어서는 안 된다.
- 자체 호스팅 엔진이 아직 데이터 준비 중이라 요청은 받지만 경로를 낼 수 없는 경우 —
  "경로 없음"으로 오인되면 사용자는 있지도 않은 경로 문제를 의심하게 된다.
- 자체 호스팅 데이터가 특정 지역만 포함하는 경우, 범위 밖 질의의 결과가 "경로 없음"과
  구별되지 않는 문제.
- 상용 API 키와 자체 호스팅 주소가 **둘 다** 저장된 상태에서 어느 것이 쓰이는지 —
  사용자가 예측할 수 없는 자동 선택이 일어나면 안 된다.
- 상시 서버(MCP) 프로세스는 사용자의 로그인 셸을 거치지 않고 기동되므로, 셸 환경에만
  존재하는 설정은 커맨드라인과 상시 서버의 동작을 갈라놓는다.
- 자체 호스팅 사용자에게 저장할 비밀값이 하나도 없는 경우, 자격증명 저장소 접근을
  요구하면 비밀이 없는데도 잠금 해제 프롬프트가 뜬다.
- 자동화·AI가 설정을 수행하는 경우 비밀값이 명령행에 남으면 셸 기록과 프로세스 목록으로
  샌다.
- 자체 호스팅 엔진과 장소 검색(건물명·주소 → 좌표) 기능의 관계 — 경로 엔진만 자체
  호스팅해도 장소 검색이 여전히 외부 상용 서비스에 의존하면 "외부 종속 제거"가 절반만
  달성된다.

## Requirements *(mandatory)*

### Functional Requirements

**제공자 선택과 설정**

- **FR-001**: 사용자는 경로 검색을 **자체 호스팅 엔진**으로 수행할지 **상용 경로 검색
  서비스**로 수행할지 선택할 수 있어야 한다.
- **FR-002**: 선택은 영속되어야 하며, 커맨드라인 경로와 상시 서버 경로가 **같은 선택을
  읽어야** 한다. 사용자의 셸 환경에만 존재하는 값에 의존하는 방식은 허용되지 않는다 —
  상시 서버는 로그인 셸을 거치지 않고 기동되므로 두 경로가 갈라진다.
- **FR-003**: 자체 호스팅을 선택한 사용자는 설정·사용 어느 단계에서도 **상용 경로 검색
  API 키를 요구받지 않아야** 한다.
- **FR-004**: 자체 호스팅 엔진의 주소는 사용자가 지정한다. 이 값은 비밀값이 아니므로
  자격증명 저장소가 아닌 일반 설정으로 취급되어야 하며, **저장할 비밀이 없는 사용자에게
  자격증명 저장소 접근을 요구해서는 안 된다**.
- **FR-005**: 초기 설정은 제공자 선택 → 제공자별 입력 → 장소 검색 설정을 **한 번의
  절차 안에서** 마칠 수 있어야 한다.
- **FR-006**: 자동화·AI가 수행할 수 있는 비대화식 설정 경로가 제공되어야 한다. 비밀값은
  **명령행 인자로 받지 않아야** 한다 — 셸 기록과 프로세스 목록에 평문으로 남는다.
- **FR-007**: 사용자는 저장된 자격증명을 삭제할 수 있어야 한다. 제공자를 전환한 사용자가
  더 이상 쓰지 않는 키를 남겨 둘 필요가 없어야 한다.
- **FR-008**: 상용 API 키와 자체 호스팅 주소가 모두 저장돼 있더라도 실제로 사용되는
  제공자는 **사용자의 명시적 선택**으로만 결정되어야 한다. 저장 여부에 따른 암묵적
  추정이나 자동 대체는 허용되지 않는다.
- **FR-035**: 자격증명 삭제는 **초기 설정 절차 안에서** 제공되어야 하며, 이를 위한 별도
  최상위 명령을 두지 않는다. 기존에 존재하던 삭제 전용 명령은 제거된다(breaking change).
  FR-007이 요구하는 삭제 기능 자체는 그대로 유지되며, 제공되는 위치만 바뀐다.
- **FR-036**: 장소 검색 설정을 지정하는 비대화식 수단은 **값을 받는 형태**여야 한다.
  사용 여부만 표현하는 불리언 형태로는 "사용 안 함"을 명시적으로 선택할 수 없어
  FR-030이 요구하는 독립 축을 표현하지 못한다. 기존 불리언 형태는 제거된다(breaking
  change). 구형식으로 호출한 사용자는 **새 형식을 안내받아야** 하며, 조용히 실패해서는
  안 된다.

**자체 호스팅 경로 검색**

- **FR-009**: 자체 호스팅 제공자로도 총 소요시간·환승 횟수·요금·단계별 안내가 기존과
  같은 항목으로 제공되어야 한다.
- **FR-010**: 원본 데이터에 없는 항목(예: 요금)은 **"정보 없음"으로 구분 표현**되어야
  하며, 0 같은 유효값으로 위장되어서는 안 된다.
- **FR-011**: 성공·실패 출력의 구조는 **제공자와 무관하게 동일**해야 한다. 기존 기계
  판독 출력 계약이 제공자별로 갈라져서는 안 된다.
- **FR-012**: 사용자와 AI는 제공자가 무엇인지에 따라 **질의 방식을 바꿀 필요가 없어야**
  한다.
- **FR-013**: 상용 API 경로의 기존 동작은 이 기능으로 인해 바뀌지 않아야 한다.

**실패 처리**

- **FR-014**: 제공자가 선택되지 않은 상태의 경로 검색은 **다른 실패와 구별되는 신호**로
  실패하고 초기 설정을 안내해야 한다.
- **FR-015**: 자체 호스팅 엔진에 연결할 수 없는 실패는 **재시도가 유효한 실패**로
  구분되어야 한다.
- **FR-016**: 자체 호스팅 엔진이 응답은 하지만 요청을 처리할 수 없는 상태는 "경로 없음"과
  **구별되는 신호**로 전달되어야 한다.
- **FR-017**: 자체 호스팅 관련 실패 안내에는 **자체 호스팅 문서의 위치**가 사람용·기계
  판독 양쪽 모두에 포함되어야 한다.
- **FR-018**: 실패 메시지 어디에도 사용자의 **사설망 호스트명·포트·경로가 노출되어서는
  안 된다**. 상시 서버 경로에서는 이 값이 AI의 대화 기록에 남는다.
- **FR-019**: 자체 호스팅 엔진의 응답 원문(내부 메시지, 추적 정보)이 사용자나 AI에게
  그대로 전달되어서는 안 된다.
- **FR-020**: 이 기능이 추가하는 실패 상황들은 기존 **망라성 게이트**에 의해 식별자
  부여가 자동으로 강제되어야 한다.

**문서**

- **FR-021**: 저장소는 자체 호스팅 구축 문서를 제공해야 하며, **필요한 데이터의 확보처 ·
  실행 절차 · naeryeo와의 연결 방법**을 모두 포함해야 한다.
- **FR-022**: 문서의 절차는 **재현 가능**해야 한다 — 실행 대상과 데이터 출처의 버전이
  고정되어, 다른 시점에 따라 해도 같은 결과에 도달해야 한다.
- **FR-023**: 문서는 착수 전에 알아야 할 **자원 요구치(저장 공간·메모리·준비 시간)의
  실측 기준값**을 명시해야 한다.
- **FR-024**: 문서는 자체 호스팅 데이터가 상용 서비스와 비교해 갖는 **한계(갱신 주기,
  포함되지 않는 정보, 지역 범위)** 를 명시해야 한다.
- **FR-025**: 시작 안내 문서에서 상용 API 키 발급이 **유일한 시작 경로처럼 보여서는 안
  된다**. 자체 호스팅이 동등한 선택지로 제시되어야 한다.
- **FR-026**: AI용 스킬 문서는 제공자 개념과 제공자별 실패 신호 분기를 반영해야 한다.
- **FR-027**: AI용 스킬 문서는 **AI가 사용자 동의 없이 자체 호스팅 환경을 설치하거나
  기동하지 않도록** 명시적으로 금지해야 한다.
- **FR-037**: 초기 설정 절차와 사용자 문서는 **자체 호스팅을 기본 제시 경로**로 삼아야
  한다 — 설정 절차에서 먼저 제시되는 선택지이자 문서에서 먼저 서술되는 경로다.
  단 이는 **제시 순서와 기본 선택지에 한정**되며, 설정이 없는 상태에서 특정 제공자로
  암묵 동작하는 것을 뜻하지 않는다. 무설정 상태의 동작은 FR-008·FR-031·FR-014가
  그대로 규정한다.

**장소 검색(건물명·주소 → 좌표)과의 관계**

- **FR-028**: 장소 검색은 **현행 방식을 그대로 유지**한다. 자체 호스팅 사용자도 건물명·
  주소로 검색하려면 기존과 동일하게 외부 장소 검색 키를 별도로 등록해야 하며, 역·정류장
  이름만으로 검색한다면 등록하지 않아도 된다.
- **FR-029**: 문서는 자체 호스팅 사용자에게 **남는 외부 의존이 무엇인지 명시**해야 한다 —
  경로 검색은 자체 호스팅으로 외부 의존이 사라지지만 건물명·주소 검색은 그렇지 않다는
  점, 그리고 그것이 선택 사항이라는 점. FR-024가 데이터의 **품질·범위** 한계를 다루는
  것과 달리 이 요구사항은 **의존성 축**을 다룬다 — 두 절은 문서에서 분리되어야 한다.
- **FR-030**: 장소 검색 설정은 경로 제공자 선택과 **독립된 축**이어야 한다. 자체 호스팅과
  상용 API 어느 쪽을 고르든 장소 검색 등록 여부를 따로 결정할 수 있어야 한다.

**기존 사용자 전환**

- **FR-031**: 이미 상용 API 키를 등록한 기존 사용자라도, 업그레이드 후에는 **제공자
  미설정 상태로 취급**된다. 저장된 키의 존재를 근거로 제공자를 추정하지 않는다 —
  FR-008의 원칙에 예외를 두지 않는다.
- **FR-032**: 그 결과로 발생하는 첫 실행 실패는 **FR-014의 "제공자 미설정" 신호**로
  전달되어야 하며, 초기 설정을 실행하라는 안내가 함께 제시되어야 한다. 사용자가 무엇을
  해야 하는지 모른 채 막히는 경우는 없어야 한다.
- **FR-033**: 이미 저장된 자격증명은 이 전환 과정에서 **삭제되지 않아야** 한다. 사용자가
  초기 설정에서 기존 제공자를 다시 선택하면 저장된 키가 그대로 재사용되어야 한다.
- **FR-034**: 이번 변경으로 기존 동작이 달라지는 지점은 릴리스 안내와 사용자 문서 양쪽에
  **사전 고지**되어야 한다. 최소한 "업그레이드 후 초기 설정을 한 번 다시 실행해야 한다"와
  그 이유가 포함되어야 한다. 고지 대상에는 최소한 다음이 모두 포함된다 — (1) 제공자
  재설정 강제(FR-031), (2) 삭제 전용 명령의 제거(FR-035), (3) 장소 검색 플래그의 형태
  변경(FR-036).

### Key Entities

- **경로 제공자 선택**: 어느 엔진으로 경로를 검색할지에 대한 사용자의 명시적 결정. 모든
  진입점이 공유하는 단일 값이며, 비밀값이 아니다.
- **자체 호스팅 엔드포인트**: 사용자가 운영하는 경로 검색 엔진의 위치. 비밀값은 아니지만
  사용자의 내부망 구조를 드러내므로 외부(사용자 출력·AI 응답)로 노출되어서는 안 된다.
- **자체 호스팅 구축 문서**: 데이터 확보처, 실행 절차, 연결 방법, 자원 요구치, 데이터
  한계를 담은 사용자 대상 문서. 실패 안내가 이 문서를 가리킨다.
- **제공자별 실패 신호**: 자체 호스팅 도입으로 새로 생기는 실패 상황들의 식별자. 기존
  실패 식별자 체계의 일부로 편입된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 상용 경로 검색 서비스 계정이 **전혀 없는** 사용자가 naeryeo로 경로 검색에
  성공할 수 있다 — 현재는 불가능하다.
- **SC-002**: 자체 호스팅 사용자가 **경로 검색**을 위해 지출하는 외부 유료 API 호출이
  0건이다. 역·정류장 이름만으로 검색하는 사용자는 외부 서비스 호출이 전혀 없이 naeryeo를
  사용할 수 있다. (건물명·주소 검색을 원하는 사용자에게 외부 장소 검색 의존이 남는 것은
  의도된 범위이며 — FR-028 — 문서로 고지된다.)
- **SC-003**: 자체 호스팅 경험이 없는 사용자가 **문서만으로** 구축을 완료한다 — 문서
  바깥의 지식이 필요했던 지점이 0건이다.
- **SC-004**: 문서를 읽은 사용자는 **착수 전에** 필요한 저장 공간·메모리·준비 시간을
  알 수 있다 — 구축 도중 예상 밖의 자원 부족으로 중단되는 경우가 0건이다.
- **SC-005**: 커맨드라인 경로와 상시 서버 경로가 서로 **다른 제공자를 사용하는 경우가
  0건**이다.
- **SC-006**: 자체 호스팅 사용자의 사설망 호스트명·포트가 사용자 출력이나 AI 응답에
  노출되는 경우가 **0건**이다.
- **SC-007**: 대표 질의 집합(수도권 도시철도, 지방 광역시 시내, 도시 간 이동)에서 자체
  호스팅 제공자가 경로를 반환한다.
- **SC-008**: 성공·실패 출력 구조가 제공자와 무관하게 동일하며, 기존 출력 계약을 검증하는
  테스트가 제공자를 바꿔도 **변경 없이 통과**한다.
- **SC-009**: 자체 호스팅 관련 실패를 만난 사용자가 **출력에 담긴 안내만으로** 복구
  경로에 도달한다 — 별도 문의 없이 문서 위치를 찾을 수 있다.
- **SC-010**: 업그레이드한 기존 사용자가 출력에 담긴 안내를 따라 정상 사용에 도달하기까지
  **초기 설정 1회 실행**만 하면 된다 — 키 재발급이나 수동 파일 편집이 필요한 경우가
  0건이다.
- **SC-011**: 신규 사용자 시작 안내에서 자체 호스팅과 상용 API가 **동등한 선택지**로
  제시된다 — 상용 키 발급이 전제로 서술된 문장이 0건이다.

## Assumptions

아래는 명세 작성 시 근거를 두고 선택한 기본값이다. 프로젝트 헌법(원칙 I: 추상화는
복잡도를 정당화해야 한다)과 기존 계획 논의(GYE-288·294·295)를 기준으로 삼았다.

- **상용 경로 검색 서비스는 계속 지원한다.** 사용자 요구는 "자체 호스팅을 **가능하게**
  하라"이지 "상용 API를 없애라"가 아니다. 자체 호스팅은 자기 인프라를 운영할 의지와
  자원이 있는 사용자를 위한 선택지이며, 그렇지 않은 사용자에게 상용 API는 여전히 가장
  빠른 시작 경로다.
- **제공자 선택은 명시적 설정으로만 결정된다.** 저장된 값의 유무로 제공자를 추정하거나
  실패 시 다른 제공자로 자동 대체하지 않는다. 자동 대체는 사용자가 어느 엔진의 결과를
  보고 있는지 알 수 없게 만들고, 자체 호스팅으로 비용을 통제하려는 사용자를 본인도
  모르게 과금 경로로 되돌린다.
- **자체 호스팅 엔진의 운영 책임은 사용자에게 있다.** naeryeo는 엔진을 설치·기동·관리하지
  않으며, 문서와 연결 수단만 제공한다. AI 에이전트가 사용자 동의 없이 엔진을 설치하는
  것은 명시적으로 금지된다.
- **자체 호스팅 엔진은 인증 없이 접근 가능한 것으로 가정한다.** 개인 장비나 사설망에서
  운영하는 것을 기본 사용 형태로 본다. 인증이 필요한 배치는 이번 범위 밖이다.
- **구축 문서는 이 저장소 안에서 관리한다.** 실패 안내가 문서를 가리키므로, 문서와 코드가
  같은 릴리스 주기로 움직여야 안내와 실제 절차가 어긋나지 않는다.
- **경로 결과 항목은 기존 구조를 그대로 쓴다.** 제공자별로 결과 구조를 나누면 기존 출력
  계약이 깨지고, 호출자가 제공자를 알아야만 결과를 해석할 수 있게 된다.
- **엔진 선택 자체(어떤 오픈소스 엔진을 쓸 것인가)는 구현 계획 단계에서 확정한다.** 이
  명세는 "사용자가 자기 인프라에서 운영하는 경로 검색 엔진"이라는 역할만 규정한다.
- **자체 호스팅 결과가 상용 서비스와 동일할 것을 요구하지 않는다.** 데이터 출처가 다르므로
  경로·소요시간이 다를 수 있고, 실시간 정보가 없을 수 있다. 이 차이는 숨기지 않고 문서로
  고지한다(FR-024).
- **장소 검색의 외부 의존 제거는 이번 범위가 아니다(사용자 결정).** 이번 기능은 과금
  압력이 실제로 존재하는 **경로 검색**의 종속을 끊는 데 집중한다. 장소 검색은 선택
  기능이고 역·정류장 이름만 쓰는 사용자에게는 애초에 필요 없으므로, 자체 호스팅의 가치를
  성립시키는 데 필수가 아니다. 자체 호스팅 엔진이 제공하는 장소 검색으로 외부 의존을
  0으로 만드는 안은 **후속 기능으로 별도 명세**한다.
- **이 기능은 breaking change를 허용하는 릴리스로 나간다(사용자 결정).** 따라서 제공자
  선택을 도입하기 위해 기존 설정 절차와 명령 표면을 바꾸는 것이 허용되며, 하위 호환을
  위해 예외 분기를 남기지 않는다. FR-031(저장된 키로 제공자를 추정하지 않음)이 이 결정에
  기대고 있다 — 무중단 업그레이드를 택했다면 FR-008의 원칙에 영구적인 예외가 하나
  생겼을 것이다.
- **설정 상태를 바꾸는 진입점을 하나로 유지한다.** 제공자 개념이 들어오면서 "설정"이 담는
  것이 자격증명 하나에서 제공자·주소·지오코더·자격증명 넷으로 늘어난다. 이 상태를 바꾸는
  명령이 둘로 갈리면 사용자는 "어디서 무엇을 바꾸는지"에 대한 모델을 두 개 유지해야 하고,
  삭제 전용 명령은 그중 가장 좁은 조각만 담당하게 되어 유지 비용이 이득을 넘는다.
  FR-035가 이 판단의 결과다.
- **재설정 강제의 비용은 고지로 상쇄한다.** 기존 사용자 전원이 첫 실행에서 한 번
  실패하는 것은 의도된 설계이며, 그 실패가 명확한 안내를 동반하고(FR-032) 릴리스 노트에
  사전 고지되는 것(FR-034)이 이를 감당 가능한 수준으로 유지하는 조건이다.

## Dependencies

- **선행(완료됨)**: 구조화된 출력 계약(spec 005) — 이 기능이 추가하는 실패 상황들은 그
  체계 위에 얹힌다. 005의 망라성 게이트가 새 실패 상황의 식별자 부여를 자동으로 강제한다
  (FR-020).
- **관련(완료됨)**: 경로 검색 API 키 평문 유출 차단(GYE-293) — FR-018·FR-019는 같은
  원칙을 자체 호스팅 엔드포인트에 확장 적용한 것이다.
- **문서 산출물 간 결합**: 실패 안내가 자체 호스팅 문서를 가리키므로(FR-017), 문서 위치가
  확정되기 전에는 안내 문구를 최종화할 수 없다.
- **후속 기능**: 자체 호스팅 엔진의 장소 검색 기능으로 건물명·주소 검색의 외부 의존까지
  없애는 작업은 이 기능 완료 후 별도 명세로 진행한다. 이 명세의 FR-030(장소 검색을 독립
  축으로 유지)이 그때 선택지를 추가할 자리를 남겨 둔다.
- **릴리스 결합**: 이 기능은 breaking change를 포함하는 릴리스로 나가며(Assumptions),
  FR-034의 사전 고지가 그 릴리스 노트에 실려야 한다.
- **계획 이력**: 이 명세는 Linear의 GYE-294(제공자 설정 모델·설정 절차 재설계),
  GYE-295(대체 경로 제공자 구현), GYE-288(자체 호스팅 레시피·문서)이 다루던 범위를 하나의
  사용자 가치("자체 호스팅 가능")로 통합한 것이다.

## Out of Scope

- **상용 경로 검색 서비스 지원 제거** — 계속 지원한다.
- **naeryeo가 자체 호스팅 엔진을 설치·기동·업데이트하는 기능** — 운영 책임은 사용자에게
  있다.
- **자체 호스팅 엔진 자체의 개발** — 기존 오픈소스 엔진을 사용자가 운영하는 것을 전제로
  한다.
- **naeryeo 프로젝트가 공용 호스팅 인스턴스를 운영하거나 준비된 데이터를 배포하는 것** —
  운영 비용과 데이터 재배포 조건이 별도 판단을 요구한다.
- **장소 검색(건물명·주소 → 좌표)의 외부 의존 제거** — 자체 호스팅 엔진의 장소 검색
  기능으로 Kakao 의존까지 없애는 안은 **후속 기능으로 별도 명세**한다. 이번 범위에서
  장소 검색은 현행 유지다(FR-028).
- **인증이 필요한 자체 호스팅 배치 지원**.
- **제공자 자동 대체(폴백) 및 제공자 간 결과 비교**.
- **v1.0.0 태깅과 배포 채널 검증** — 별도 릴리스 작업으로 다룬다.
